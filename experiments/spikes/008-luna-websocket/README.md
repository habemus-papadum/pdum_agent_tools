# 008 — Live Luna WebSocket capture and cost

Run `pnpm spike:008`. This makes **one live `gpt-6-luna` turn**, using the installed Codex executable, raw app-server protocol, and the MITM runner from Spike 004. It does not simulate the provider and never falls back to a more expensive model. Install the root pnpm and uv workspaces first. `SPIKE_CODEX_BIN` selects a different executable; the default explicitly resolves `~/.local/bin/codex`.

The prompt requests only `REGULAR_OK`, with low reasoning effort, web search disabled, no requested tools, and an isolated read-only working directory. The reused runner limits elapsed time to 90 seconds, injects the existing subscription access token without refreshing it, and checks that the original auth file is unchanged. It uses a run-local CA and does not change system trust. One turn may include a separate no-generation warmup request.

`pnpm spike:008 --capture /absolute/path/to/artifacts/004-codex-traffic/<run>-live` analyzes an existing live capture without another model call. Evidence stays under ignored `artifacts/004-codex-traffic/` and `artifacts/008-luna-websocket/`. The analyzer checks the actual model, successful WebSocket upgrades, both message directions, absence of HTTP/SSE inference fallback, complete captured JSON, zero reported dropped events, the completed answer, and response usage. It correlates this probe's sequential requests to response IDs and deduplicates completed responses before estimating cost. It is not a general multiplexed Responses protocol analyzer.

## What the MITM already does

The existing [002 capture addon](../002-claude-traffic/python/capture.py), reused by [004's adapter](../004-codex-traffic/python/capture.py), already handles WebSockets. Codex routes HTTPS through the loopback proxy and trusts its private CA; the proxy terminates TLS locally and establishes separately verified upstream TLS. After the HTTP Upgrade, mitmproxy calls `websocket_message` for each reassembled application message.

The addon writes direction, flow ID, timestamp, opcode, byte count, payload hash, and parsed/redacted JSON to `level2.jsonl`. That includes client `response.create`, server deltas, response lifecycle events, usage, and protocol-specific events it does not otherwise interpret. This is **decrypted application-message capture**, not TCP packets or original WebSocket frame boundaries. It does not need a new WebSocket implementation or offline TLS decryption to capture this traffic.

Our live sequence was a warmup (`generate: false`), its response ID, and a generating request referring to that ID via `previous_response_id`. The smaller second request is not the complete conversation: recording only final requests or assistant text loses context. The official [WebSocket guide](https://developers.openai.com/api/docs/guides/websocket-mode) documents these warmup and incremental-input mechanics. WebSocket is still a transport for the **Responses API**, not an alternative to Responses; the synthetic fixtures were the part we are replacing with live validation.

## Minimum infrastructure to build next

1. **Keep capture separate from interpretation.** Retain ordered, schema-agnostic application messages; derive readable requests, context chains, and usage offline. Index run, connection, response, thread, parent-thread, turn and item IDs where available. Store unknown message types rather than dropping them because a decoder is outdated.
2. **Make completeness measurable.** Add connection-open/close/reconnect/error records, per-connection sequence numbers, explicit truncation/gap markers, and capture-health counters. Correlate Level 1 IDs with Level 2 headers and response IDs. Capture both HTTP/SSE and WSS because Codex can fall back. Do not assume exactly one response or one connection per turn.
3. **Bound resource use without silent loss.** The spike currently limits a file to 32 MiB and retained bodies/messages to 1 MiB; non-JSON or unsupported encodings can become hash/metadata only. Rotate files and add retention policies, bounded write queues, and a deliberate overflow policy. mitmproxy reassembles a complete WebSocket message before our hook; these file/body limits are not a global RAM cap. Validate concurrency, large messages, and compression before running swarms. This live probe disables Codex request compression and does not validate every encoding.
4. **Separate safe summaries from sensitive evidence.** Current captures redact authentication fields and identifiers, but prompts, code, images, tool results, and URLs can still be sensitive. Any more complete binary/raw-body archive needs explicit opt-in, private permissions, encryption/access control and retention. Preserve redaction metadata so a sanitized capture is not mistaken for a byte-identical replay artifact. Never alter system-wide trust or the developer's credential files.
5. **Account for usage, not packet volume.** Aggregate terminal response usage once per response ID, retaining model, service tier, cache reads/writes, reasoning/output tokens, retries and warmups. Keep estimates and actual billing distinct. Budget checks before subsequent turns are useful, but post-response accounting cannot enforce a hard pre-request dollar limit.

There is no need to build a large interception framework before the next experiments: this recorder is sufficient for bounded live debugging. The next valuable step is connection/sequence/completeness metadata and an offline usage/context viewer. Longer-lived production capture needs the resource, privacy and reconnect work above. Environment proxy variables do not guarantee interception of arbitrary tools, MCP subprocesses, direct sockets or remote workers.

## Pricing and validation boundary

Rates were checked on 2026-10-12 against the [official Luna model page](https://developers.openai.com/api/docs/models/gpt-6-luna): Standard short-context prices per million tokens are $0.10 uncached input, $0.01 cached input, $0.125 cache writes, and $0.50 output. The analyzer rejects long-context or non-default generated-response tiers rather than silently using these rates. Recheck rates before relying on estimates after an upgrade.

The probe uses subscription auth, so these are **API-equivalent estimates, not measured charges**. Warmup usage is shown separately, and its Standard-rate equivalent is included in an additional sanity-check total without asserting the subscription bills it that way. No paid tool calls are requested. Fixtures remain useful for deterministic parser regressions or intentionally malformed traffic, but live low-cost calls are now the default evidence for provider behavior.
