# Agent evals: one task, several agents, comparable numbers

This directory lets an agent (or a person) give the same bounded coding task to Codex,
Claude Code or an agent of our own, measure the run from its trace, grade the result,
and compare both against baselines recorded on 17 October 2026. The findings those
baselines came from are in [docs/context-consumption.md](../../docs/context-consumption.md).

The eval reads only two things: the worktree the agent worked in and a history file in
the shared agent-history schema. Codex and Claude Code get there through
`pdum-history ingest`; any other agent gets there by writing its trace in that schema.
Nothing in the measurement or grading knows which agent ran.

## Layout

| Path | What it is |
| --- | --- |
| `tasks/<task>/prompt.txt` | The exact prompt, identical for every agent. |
| `tasks/<task>/checks.sh` | Objective gates run on the worktree; prints `CHECK <name> ok|FAIL` lines. |
| `tasks/<task>/expectations.json` | Strings the deliverable must contain (routes, wire field names) and a minimum test count. |
| `configs/*.toml` | One agent configuration per file: agent kind, model, effort, window, profile template. |
| `baselines/<task>/<date>.json` | Metrics of the reference runs and their envelope, generated by `report.py`. |
| `bin/` | `prepare.py`, `run.py`, `ingest.py`, `report.py`, `archive.py`. |
| `$EVALS_HOME` (default `~/history/evals/`) | Raw data per run: transcripts, `history.duckdb`, worktree patch, logs, report. Never in git. |

## Running one arm

Run from any checkout of this repository. Worktrees are created from `main` under
`~/src/exp-evals/<run-id>` and profiles under `~/src/exp-evals/profiles/`; your own
`~/.codex` and `~/.claude` are read for auth and config and never written.

```sh
EVALS=experiments/evals
PY="uv run --frozen --all-packages python"
RUN=$($PY $EVALS/bin/prepare.py $EVALS/configs/codex-astra-default.toml)   # prints the run id
$PY $EVALS/bin/run.py $RUN                                                  # one non-interactive turn
$PY $EVALS/bin/ingest.py $RUN                                               # transcripts, history.duckdb, patch
$PY $EVALS/bin/report.py $RUN --baselines $EVALS/baselines/launcher-client/2026-10-17.json
```

Add `--suffix r2` to `prepare.py` for a repetition of the same config on the same day.
Run arms one after another, not in parallel, so wall time stays comparable. A full run
of the three baseline configs takes about 30 minutes and roughly $15 of list-price usage
on the launcher-client task. Rules during a run: never answer a question the agent asks,
never touch the worktree, never run anything heavy on the machine.

`report.py` prints and saves `report.md`: the run's metrics beside the baseline envelope,
the gates, the expectation coverage, flags, and a rubric to score by hand after reading
the worktree. `metrics.json` holds the same numbers for scripts.

## Reading the result

- **FAIL** flags mean the run did not deliver: a gate failed, the exit code was not zero,
  Python was touched, a required route is missing, or the agent ended with a question.
- **WARN** flags mean the run is outside half-to-double the baseline range on wall time,
  steps, tool calls, tool output bytes, peak context, growth per step, output tokens,
  context read or cost, or that the transcript shows no test run. A warning is a reason to
  read the transcript, not a verdict: the three baselines themselves span 7 to 14 minutes
  and $3.3 to $7.8.
- **TOO GOOD** means every gate passed with very few steps or minutes. Confirm in the
  transcript that the agent ran the tests and typecheck itself; `checks.sh` passing on a
  package the agent never tested is a different outcome from the agent verifying its work.
- The rubric (route coverage, type fidelity, tests, gates, README, scope; 0 to 3 each) is
  scored by reading `worktree.patch` against the Python handlers. The baselines scored 15,
  15 and 16 of 18.

Baseline envelope for `launcher-client` (one run per arm, so treat it as a range of
plausible outcomes, not a distribution):

| Metric | Low | High |
| --- | ---: | ---: |
| Wall time (minutes) | 7.0 | 14.3 |
| Model steps | 22 | 25 |
| Tool calls | 34 | 59 |
| Peak context (tokens) | 92k | 185k |
| Context added per step | 3.4k | 6.9k |
| Output tokens | 19k | 72k |
| Cost (list, USD) | 3.3 | 7.8 |

## Adding an agent

Copy `configs/custom-command.example.toml`, set `run` to the command that launches the
agent on `{worktree}` with `{prompt_file}`, and make the agent write its trace into
`{run_dir}/history.duckdb` in the shared schema (`pdum-history schema --json` prints it;
the TypeScript package exports the same contract). At minimum fill `threads`, `turns`,
`responses` (one row per model call with `input_tokens`, `cached_input_tokens`,
`cache_write_input_tokens`, `output_tokens`, `model`, `ts`) and `items` (tool calls with
`item_type`, `command`, `output_bytes`, `status`). Set `window` in the config unless the
agent writes `token_counts.model_context_window`. Then the four commands above apply
unchanged, and `report.py` prices the run if its model is in the price table.

## Adding a task

Create `tasks/<name>/` with `prompt.txt`, a `checks.sh` that prints `CHECK` lines for the
task's gates, and an `expectations.json` naming the strings the deliverable must contain.
Run each reference agent once with `prepare.py`, `run.py`, `ingest.py` and
`report.py --no-checks` or with checks, then build the envelope:

```sh
$PY $EVALS/bin/report.py --make-baseline $EVALS/baselines/<name>/$(date +%F).json RUN_A RUN_B RUN_C
```

A second, shorter task is planned (adding the context-consumption questions to the
agent-history package) so the battery has a quick check and a long one.

## Registering a run made by hand

`archive.py import` writes `run.json` for a run that was launched outside these scripts,
given its worktree, profile and logs; `ingest.py` and `report.py` then work as usual. That
is how the 17 October runs became the first baseline.

## Cleaning up

Worktrees: `git worktree remove ~/src/exp-evals/<run-id>` from the repository, then
`git branch -D eval/<run-id>`. The patch in the run directory preserves the result.
Profiles: delete `~/src/exp-evals/profiles/<run-id>`; they hold copied auth, so do not
share them. Run directories under `$EVALS_HOME` are the record; keep them.
